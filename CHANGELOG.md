# Changelog

Все заметные изменения проекта — здесь, по датам, новые сверху. Формат
свободный (без строгого SemVer — деплой непрерывный, не по релизам), но
каждая запись — одна строка на смёрженную ветку: что изменилось и зачем,
номер `#N` и короткий hash merge-коммита — тот же, что появляется в футере
UI / `docker inspect ... image.revision` после деплоя этого коммита.
**С 4 авг. 2026 (переход на локальный git, GitHub-аккаунт `ivank-hvac`
заблокирован — см. CLAUDE.md)**: `#N` больше не настоящий номер GitHub PR,
это условный ручной счётчик, продолжающий ту же нумерацию.

  (`app.js` по-прежнему грузит весь `/graph.json`) — чисто аддитивно,

## 2026-08-20

- Переключение языка на экране «незавершённая сессия» больше не ломает
  интерфейс. Смена языка перерисовывала экран через `render()`, а тот рисует
  текущий узел графа — экран возобновления узлом не является, поиск упирался
  в `undefined`, и карточка стиралась целиком. Поймал реальный пользователь,
  перейдя на русский. Экран теперь помнит, что показывает не узел, и
  перерисовывается на месте. (#81, `f784514`)


- Лимиты и статистика впервые считают реального клиента, а не пир туннеля.
  За edge-прокси `request.client.host` всегда был адресом прокси, поэтому все
  посетители сидели в одном ведре и один вызывающий мог исчерпать лимит для
  всех. Внутренний Caddy разрешает адрес по собственному `trusted_proxies` и
  передаёт результат одним заголовком, так что приложению не приходится
  гадать, какое звено `X-Forwarded-For` не подделано. (#78, `82e5327`)
- Вывоз логов вынесен из контейнера на хост. Логирующий драйвер, ходящий в
  сеть, вычисляется при создании контейнера — на загрузке машины, до
  появления маршрутов, контейнер не создаётся вообще, и политика перезапуска
  не спасает, потому что падения не было. Один такой ребут уронил сайт.
  Отправка теперь читает файл и досылает по TCP с дисковой очередью, а
  локальные логи ограничены по размеру. (#79, `82e5327`)
- На панель добавлен раздел «узлы, из которых чаще всего зовут ассистента».
  Смысл не в метрике: узел, про который регулярно спрашивают, — это место,
  где граф недоговаривает, то есть список задач по контенту. (#80, `82e5327`)


- Ассистент закрыт двумя слоями, ни один из которых не пытается распознать
  атаку. Первый структурный: запрос обязан нести сессию, реально прошедшую
  граф, — у скрипта, бьющего в эндпоинт напрямую, её нет, и перефразированием
  это не обходится. Второй ограничивает сутки, а не минуту: лимит в минуту
  при достаточном числе минут допускает любой расход. Квота списывается до
  обращения к провайдеру — неудачный запрос тоже тратит её, что осознанно
  консервативно, раз защищаем оплачиваемый ключ. Счётчики в отдельной
  таблице, чтобы `ai_calls` осталась агрегатной и без привязки к сессии.
  Интерфейс предупреждает с половины остатка и явно на последней десятой.
  Обе переменные проброшены через compose — иначе значения в `.env` не
  действовали бы, то же упущение, что ловили в #38 и #59. (#76, `e5a5482`)
- Логи Caddy уезжают на отдельную машину по мере записи. Логи, лежащие
  только на атакуемом хосте, теряются вместе с ним и правятся первыми.
  Транспорт UDP намеренно: syslog-драйвер Docker подключается при старте
  контейнера, и недоступный TCP-приёмник не дал бы контейнеру подняться,
  поставив прод в зависимость от коллектора. (#77, `e5a5482`)


- `basicauth` переименован в `basic_auth`. Caddy сменил написание в 2.8 и с
  тех пор предупреждает о старом при каждом старте — с только что включёнными
  логами это был бы шум в каждом рестарте. Инструкции в `DEPLOY.md` и
  `commands.md` поправлены вместе с конфигом, чтобы не разъезжались; в
  комментарии оговорено, что self-host на Caddy старше 2.8 требует старого
  написания. (#75, `7033616`)


- Включено логирование запросов в Caddy. По умолчанию Caddy не пишет ничего,
  то есть и инцидент, и пентест не оставили бы следа вообще. JSON в stderr,
  чтобы `Caddyfile` не обзаводился путями конкретного хоста: для обычного
  self-host'а работает `docker compose logs`, а деплой, вывозящий логи
  наружу, читает их из лога контейнера. Заголовки запросов намеренно не
  логируются — иначе `Authorization` клал бы пароль от basic auth открытым
  текстом в каждую строку. (#74, `c986f78`)
- Числовые поля измерений ограничены 10 символами: шесть цифр, разделитель и
  знак покрывают любое реальное показание давления, температуры, тока или
  микрон. Кап стоит и на поле, и в `sanitizeNumericInput` — второе ловит
  вставку. Заодно снят остаточный случай, когда к значению дописывается
  единица измерения и сумма подбиралась к серверному пределу в 400
  символов. (#73, `c986f78`)


- Свободные текстовые поля получили клиентский предел длины и счётчик
  остатка символов. Раньше сервер резал запрос (`MAX_ANSWER_FIELD_LEN=400`,
  `MAX_FREE_TEXT_LEN=2000`), а фронт об этом не знал вообще — техник,
  написавший длинное описание, получал 422 без объяснений и терял текст.
  Пределы вынесены в константы-зеркала серверных, счётчик тихий и
  подсвечивается только на подходе к лимиту, место под него зарезервировано,
  чтобы поле не прыгало при наборе. Отдельный случай — описание в
  component-check: находка сохраняется одним склеенным полем «текст узла —
  описание», поэтому честные 400 всё равно упирались бы в 422; предел там
  считается за вычетом длины текста узла. (#72, `f9a92af`)

## 2026-08-19

- Подготовка прода к пентесту, первый заход. Контейнер приложения больше не
  работает под root — заведён служебный пользователь `hvac` (uid/gid 10001);
  при апгрейде существующего деплоя нужен разовый `chown` тома, иначе SQLite
  открывается только на чтение и приложение отдаёт 500 (воспроизведено на
  тесте, процедура описана в DEPLOY.md). `GET /api/session/{id}` перечисляет
  колонки явно вместо `SELECT *` — эндпоинт неаутентифицированный, и колонка
  `ip`, добавленная позже для панели, до этого уходила в ответ. Резервный
  генератор id сессии строит UUIDv4 через `crypto.getRandomValues` вместо
  `Date.now()+Math.random()`: `randomUUID` доступен только в secure context,
  то есть на любом self-host по HTTP работала именно предсказуемая ветка.
  Выставлен `busy_timeout` у SQLite — как страховка, а не как исправление
  наблюдавшейся проблемы: 60 параллельных записей с payload ~28 КБ не дали
  ни одной блокировки и без него. (#71, `7f7dec2`)

## 2026-08-18

- В шапку обоих README добавлен абзац об авторстве: диагностический контент —
  от автора-энтузиаста, код вокруг в основном написан с Claude Code, в
  коммитах стоит трейлер `Co-Authored-By`. Нужно потому, что после

  инструмента с диагностическими советами имеет право на прямой ответ, что
  это значит. Явно сказано, что сочинение советов по HVAC со стороны ИИ —
  баг, который ревью и должно ловить. (#70, `55f8a48`)

  он говорит, какую именно ревизию крутит этот деплой. Локализована,

- Репозиторий подготовлен к публикации: `LICENSE` (**AGPL-3.0** — выбрана
